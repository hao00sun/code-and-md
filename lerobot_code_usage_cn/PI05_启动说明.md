## 2. 启动 PI05 server 端推理：TCP 方式

这是当前推荐给分离式 client 使用的 server 启动方式。server 端只负责加载 PI05 模型并返回动作，不直接控制机械臂。

```bash
cd /home/wu/lerobot_space/lerobot

env -u ALL_PROXY -u all_proxy \
  HF_HOME=/data/SUN_ht/pi/cache/huggingface \
  TRANSFORMERS_OFFLINE=1 \
  HF_HUB_OFFLINE=1 \
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --client_timeout_s 0 \
  --print_action
```

参数说明：

- `--policy_path`：要加载的 PI05 checkpoint。
- `--host 0.0.0.0`：监听所有网卡，其他机器可以通过本机局域网 IP 连接。
- `--port 5005`：server 端口。
- `--transport tcp_pickle`：使用 TCP pickle 协议。
- `--action_mode chunk`：每次推理返回一个动作块，而不是单步动作。
- `--client_timeout_s 0`：关闭 client 空闲超时。
- `--print_action`：在 server 日志中打印模型输出动作，便于检查。

启动后会打印类似：

```text
[SERVER] Client URL: tcp://本机IP:5005
```

client 端连接这个 IP 和端口即可。

## 4. PI05 server 端冻结某些关节/机械臂

`pi05_server.py` 支持只让 PI05 输出控制某些关节，其余关节自动保持 client 发来的当前 `qpos/state`。这样返回给 client 的仍然是完整 14 维动作，但未启用的维度会被当前位姿覆盖，在实际机器人上表现为“冻结该关节/该机械臂”。

14 维动作顺序如下：

```text
0  left_joint1.pos
1  left_joint2.pos
2  left_joint3.pos
3  left_joint4.pos
4  left_joint5.pos
5  left_joint6.pos
6  left_gripper.pos
7  right_joint1.pos
8  right_joint2.pos
9  right_joint3.pos
10 right_joint4.pos
11 right_joint5.pos
12 right_joint6.pos
13 right_gripper.pos
```

只让左臂行动、冻结右臂：

```bash
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --active_arms left \
  --client_timeout_s 0 \
  --print_action
```

只让右臂行动、冻结左臂：

```bash
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --active_arms right \
  --client_timeout_s 0 \
  --print_action
```

只让右臂行动、冻结左臂，并且冻结左臂时不用 client 当前 `qpos/state`，而是使用当前训练数据集里的左臂参考位姿：

```bash
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --active_arms right \
  --frozen_action_source dataset_mean \
  --frozen_action_dataset /data/SUN_ht/datasets/arx_0723_1401 \
  --client_timeout_s 0 \
  --print_action
```

其中：

- `--frozen_action_source current_state`：默认方式，冻结维度使用 client 发来的当前关节状态。
- `--frozen_action_source dataset_mean`：冻结维度使用数据集中 action 的均值。
- `--frozen_action_source dataset_median`：冻结维度使用数据集中 action 的中位数。
- `--frozen_action_source dataset_first`：冻结维度使用数据集中第一帧 action。
- `--frozen_action_source values`：冻结维度使用 `--frozen_action_values` 手动传入的 14 维数值。

只输出指定关节，例如只让左臂 1、2、3 号关节和左夹爪动：

```bash
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --active_action_dims 0,1,2,6 \
  --client_timeout_s 0 \
  --print_action
```

也可以用关节名：

```bash
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --active_action_dims left_joint1,left_joint2,left_joint3,left_gripper \
  --client_timeout_s 0 \
  --print_action
```

注意：冻结逻辑依赖 client 每次请求中携带当前 `qpos`、`state` 或 `observation.state`。如果 client 不发送当前关节状态，server 无法知道要保持在哪个当前位姿。

## 5. PI05 训练时 action loss mask

当前工程已经给 PI05 增加了训练时 action loss mask 功能。它的作用是：PI05 仍然预测完整 14 维动作，但训练 loss 只在指定动作维度上求平均，其余维度不参与 loss。这个功能用于“双臂数据、单臂运动”的情况，避免几乎静止的机械臂维度过于容易拟合，从而干扰真正运动臂的学习。

代码位置：

```bash
src/lerobot/policies/pi05/configuration_pi05.py
src/lerobot/policies/pi05/modeling_pi05.py
```

当前 14 维动作顺序：

```text
0  left_joint1.pos
1  left_joint2.pos
2  left_joint3.pos
3  left_joint4.pos
4  left_joint5.pos
5  left_joint6.pos
6  left_gripper.pos
7  right_joint1.pos
8  right_joint2.pos
9  right_joint3.pos
10 right_joint4.pos
11 right_joint5.pos
12 right_joint6.pos
13 right_gripper.pos
```

对 `/data/SUN_ht/datasets/arx_0723_1401` 的统计显示：右臂 7-13 维变化明显，左臂多个关节变化很小。因此当前 `pi05_semantic.yaml` 已配置为只对右臂计算 action loss：

```yaml
policy:
  action_loss_active_arms: right
  action_loss_active_dims: [7, 8, 9, 10, 11, 12, 13]
```

含义：

- `action_loss_active_arms: right`：便捷说明当前主要训练右臂。
- `action_loss_active_dims: [7, 8, 9, 10, 11, 12, 13]`：明确指定参与 loss 的动作维度。
- 如果 `action_loss_active_dims` 存在，它会优先于 `action_loss_active_arms`。
- 其他维度仍然保留在数据和模型输出中，但不参与训练 loss。

如果想训练左臂，把配置改为：

```yaml
policy:
  action_loss_active_arms: left
  action_loss_active_dims: [0, 1, 2, 3, 4, 5, 6]
```

如果想恢复双臂一起训练，可以删除 `action_loss_active_dims`，并设置：

```yaml
policy:
  action_loss_active_arms: both
```

注意：loss mask 只影响训练 loss，不会自动冻结推理端。推理端仍然需要配合 server 端冻结参数。例如当前只训练右臂时，推理建议：

```bash
python pi05_server.py \
  --policy_path /mnt/bigdata/SUN_ht/runs/pi05_arx_0723_1401_2026-07-23_15-49-42/checkpoints/014000/pretrained_model \
  --host 0.0.0.0 \
  --port 5005 \
  --device cuda \
  --transport tcp_pickle \
  --action_mode chunk \
  --active_arms right \
  --frozen_action_source dataset_mean \
  --frozen_action_dataset /data/SUN_ht/datasets/arx_0723_1401 \
  --client_timeout_s 0 \
  --print_action
```

这条推理命令表示：右臂使用模型输出，左臂使用数据集参考位姿，不使用 client 传来的左臂当前位姿。

训练日志中的 `loss_per_dim` 仍会记录全部真实 action 维度的逐维 loss，方便观察；真正用于反向传播的是 mask 后的 `masked_losses.mean()`。

## 10. 本地推理动作滤波、平滑、限幅

默认脚本中开启了简单动作平滑/限幅：

```bash
ACTION_FILTER_ALPHA=0.5
ACTION_MAX_DELTA=0.05
ACTION_SMOOTH_MAX_STEP=0.05
```

含义：

- `ACTION_FILTER_ALPHA`：EMA 滤波系数，越小越平滑；`1` 表示关闭 EMA 滤波。
- `ACTION_MAX_DELTA`：单个控制周期内动作变化最大值；`0` 或负数表示关闭。
- `ACTION_SMOOTH_MAX_STEP`：发送给机械臂前的分段平滑步长；`0` 表示关闭。

关闭全部滤波和平滑：

```bash
ACTION_FILTER_ALPHA=1 \
ACTION_MAX_DELTA=0 \
ACTION_SMOOTH_MAX_STEP=0 \
./innov_il/run_innov_pi05_local_inference.sh
```

## 11. 本地推理归零功能

本地推理启动后，按 `Enter` 开始策略控制。策略控制过程中按 `z`：

1. 停止继续发送 PI05 推理动作；
2. 清空动作块缓存；
3. 执行机械臂回零/回 home 动作；
4. 回零完成后退出控制循环。

默认左右臂都回零：

```bash
ZERO_ARMS=both ./innov_il/run_innov_pi05_local_inference.sh
```

只让左臂回零：

```bash
ZERO_ARMS=left ./innov_il/run_innov_pi05_local_inference.sh
```

只让右臂回零：

```bash
ZERO_ARMS=right ./innov_il/run_innov_pi05_local_inference.sh
```

禁用按 `z` 回零：

```bash
ZERO_ARMS=none ./innov_il/run_innov_pi05_local_inference.sh
```

只执行回零，不加载模型、不推理：

```bash
ZERO_ONLY=1 ./innov_il/run_innov_pi05_local_inference.sh
```

默认回零目标：

```bash
HOME_JOINTS=0,0,0,0,0,0
HOME_GRIPPER=1.0
```

其中 `HOME_GRIPPER=1.0` 表示夹爪回到打开位置。若想保持当前夹爪位置：

```bash
HOME_GRIPPER=keep ./innov_il/run_innov_pi05_local_inference.sh
```

## 14. 常见问题

### 14.1 串口权限不足

如果报错：

```text
Permission denied: '/dev/ttyACM1'
```

临时解决：

```bash
sudo chmod a+rw /dev/ttyACM0 /dev/ttyACM1
```

长期解决：

```bash
sudo usermod -aG dialout $USER
```

然后重新登录系统。

### 14.2 离线权重仍然尝试联网

启动命令中要保留：

```bash
HF_HOME=/data/SUN_ht/pi/cache/huggingface
TRANSFORMERS_OFFLINE=1
HF_HUB_OFFLINE=1
```

同时清理代理变量：

```bash
env -u ALL_PROXY -u all_proxy
```

### 14.3 OpenCV 视频打不开

如果视频是 AV1 编码，某些 OpenCV 环境可能打不开。可以用 `ffprobe` 检查：

```bash
ffprobe -hide_banner -v error -show_streams 视频路径.mp4
```

如果看到：

```text
codec_name=av1
```

而 OpenCV 读帧失败，通常是解码器支持问题，不一定是视频损坏。可转成 H.264：

```bash
ffmpeg -y \
  -i 输入.mp4 \
  -c:v libx264 -pix_fmt yuv420p -crf 23 \
  输出_h264.mp4
```
